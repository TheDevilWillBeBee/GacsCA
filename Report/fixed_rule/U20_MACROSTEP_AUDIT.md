# U20 clean-domain macrostep audit

The candidate uses one Q=8192, U=1048576, radius-seven, 6465-bit physical rule. Its complete optimized own-rule description has 14830 operations and digest `16bf88a1d4ff5496cd3b61a1200f8a809db1438472a9191fded26de3a0786257`. Depth is encoded in cells, not selected by the backend. Gray pp.31–32 motivate the specialized Address-dependent hard-wiring after ProgramBit projection; Gács §§9.2–9.3 allow an identical or suitably modified self-correcting rule to be simulated. This report describes what was executed; it does not infer the full correction theorem from clean-domain examples.

`run_dual_gather20_events.py` initializes 15 distinct projected upper cells in 15 lower colonies. Its three gather stages execute the literal physical clock successor at all 34245 source launches and 34245 receives, retain the same Data bank across stages, check all 34245 history words and 5355 Info words, and check unique physical packet phases and traveled distances. Between endpoints it computes packet flight from the checked phase/velocity invariant; it does not step the full ring.

`run_dual_capture20_events.py` loads all 390 used own-rule static inputs from the candidate's Address-projected ROM. A literal full 8192-site F ring transition captures the gathered Data into the evaluator; every captured site equals the expected encoded evaluator entry. The evaluator then runs continuously for 65536 ticks: 26101 packet deliveries, 14851 gate completions and 119 output events. At all 119 arrivals, 595 literal full-F local steps verify fivefold Holder commits. The two Flag Hold values feed ten literal holder SEND fetch/emit/receive paths, followed by a full-F Signal-capture ring step and ten checked Signal copies.

`run_dual_macrostep20_events.py` keeps that state into stage three. A packed CPU implementation of the exact physical Flag recurrence matches full-F ring steps at the Signal quiet point, stage-three reset, traveling HALT, Wf end, final reset/capture, and U−1 Info commit. The ordinary stage-three HALT head traverses static ROM sites 0 through 8185 before halting at 8186; its inertness at those sites was checked against the physical core transition. The final stage's overlay suppresses the holder head. The same encoded evaluator then runs a second continuous 65536-tick period. It checks 119 physical output arrivals through 595 fivefold local commits and compares all 119 decoded upper Info words at U−1 with the intended complete upper local F, used only as an oracle.

Three inputs passed: upper Age U−1, seed 2026092928 (87 changed projected words); upper Age0, same seed (86 changed); and upper Age0, seed 2026092951 with zero upper Signal/Wf geometry (early Flag Hold values both zero; 77 changed). Runtime was 97–105 seconds and peak CPU RSS 0.65 GiB, within the user's 40 GiB allowance. Receipts are `figs/fixed_rule/stream28_dual_macrostep20_events_v3.json`, `stream28_dual_macrostep20_age0_v1.json`, and `stream28_dual_macrostep20_quiet_v1.json`. The first two predate the optional quiet-geometry parameter in the script; numerical results remain but source hashes should be refreshed for source-sealed publication.

Two executor assumptions initially failed. The stage-three HALT head does not disappear immediately after reset; it travels across the ROM, so the audit now checks that path and the actual HALT transition. At the final reset no holder HALT head starts because the overlay suppresses it; the audit now verifies this. Neither failure was a wrong decoded result, but both exposed important physical timing details.

The skip conditions are not a proof of a continuous physical U-period. In particular, full-ring in-flight packet interference across every skipped tick, successive upper macrosteps on a closed upper ring, damaged ROM maintenance, finite-depth termination, and noise amplification remain open. A literal GPU complete-F backend is the next independent verification step. It must preserve all physical raw words in its state and perform no host upper transition or depth dispatch.

## CUDA pilot

`stream28_dual_dense_gpu20.{py,cu}` now compiles exactly the same 14830-operation complete own-F into one fixed CUDA local kernel, retains all 421 raw words per physical cell, and accepts no hierarchy depth or upper transition. A 17-site ring matched the independent native F after one tick, and a successive five-tick regression passed. On the A100, one Q8192 ring took 0.0574 seconds per dense physical tick over 100 ticks; 15 colonies took 0.847 seconds per tick over ten ticks. This implies roughly 16.7 hours for one colony or 247 hours for 15 colonies at U1048576, assuming constant throughput. The GPU allocation was 69.6 MB for one colony and 842 MB for 15. Dense GPU execution is an independent local oracle, not a realistic full-cycle backend.

The dense timing reflects an intentionally simple reference kernel, not an optimized throughput limit. It launches only four 64-thread blocks (256 workers total), with each worker looping all its assigned physical cells. Per cell the wrapper loads all 15×421 neighborhood words, even though the compiled expression uses a subset, and stores all421 output words. It executes the 14830-operation straight-line description using device workspace rather than a specialized register-resident computation. The input state is site-major, so neighboring workers reading the same field access strided addresses. A 31-colony ring would give each worker 992 sequential sites; the often quoted 1.75 s/tick is the *linear extrapolation* 0.847×31/15, not a measured 31-colony timing. These were the avoidable bottlenecks targeted by the later redesigned backend.

The redesigned dense backend and its measured approximately 125-fold improvement at 31 colonies are now documented in [DENSE_GPU_EXECUTOR20.md](DENSE_GPU_EXECUTOR20.md). Its 16.35-hour four-U estimate supersedes the old 85-day **reference-kernel** extrapolation for that ring size. The Q² full-raw memory obstacle below remains.

`stream28_dual_flags_gpu20.{py,cu}` retains every physical Flag1/Flag2 bit, applies the same radius-five recurrence by CUDA graph, and has no front-shape assumption. It matched the independent CPU recurrence across Wf start/end and a 16384-tick active window; the latter took 0.033 seconds on GPU. The full macrostep audit can select this GPU backend for the Flag portion while keeping gather/holder event checks and spatial evaluator on CPU. This is a hybrid audit of a full period, **not** an entire physical work period executed on GPU. A fully GPU-resident sparse holder and evaluator state machine is still required to satisfy that stronger target.

The specialized `stream28_dual_spatial_gpu20.{py,cu}` now stores all 267 encoded spatial words per site plus evolving gate, route and mail registers on GPU. It applies the physical radius-one spatial local transition at every tick; no host DAG or upper transition is injected. A Q8192 pilot took 0.0262 seconds per 1000 ticks. The full hybrid audit `stream28_dual_macrostep20_quiet_gpu_hybrid_v1.json` **passed** at upper Age0, seed 2026092951, zero Signal/Wf geometry: both GPU evaluator periods ran for65536 ticks and matched the independent CPU replay's complete8192-site state, all119 output arrivals,26101 packet deliveries,14851 gate completions plus63 at the next wrap. Device memory for one spatial period was19,333,136 bytes; GPU parity calls took2.042 and1.753 seconds. The GPU Flag recurrence ran393216 literal suffix ticks. The full event-composed work-cycle audit took114.475 seconds, peak CPU RSS801608 KiB, and decoded all119 upper words equal to the upper local F;77 changed. This verifies GPU execution of the physical computation and Flag recurrence across one work cycle. Holder/gather packet flights and local commits remain CPU-checked event composition, so an all-fields continuous GPU work cycle remains open.

The first combined GPU attempt reached the U−1 checkpoint before failing because its diagnostic age returned U rather than Age0. A direct wraparound parity test caught and fixed that wrapper error. The next attempt matched the complete early evaluator state and all output events but reported14914 gate completions versus the CPU's14851 because the GPU counted63 literal gates at the wrap into the next period. The CPU reports those separately; the verifier now checks both counts and the full retry passed. Neither issue changed the physical transition.

An additional canonical one-colony packet-flight fixture placed a fivefold replicated rightward holder packet at physical site100, with no head and a target absent from the ROM. The complete GPU F ring and independent native CPU F ring agreed at **every raw word after 32 literal ticks**; the packet reached site132 carrying its original data. The exhaustive 32-tick regression took115.162 seconds because native Python ring decoding dominates. After this full check, the routine test was shortened to four full CPU/GPU ticks plus a 32-tick GPU arrival and uniqueness check, preserving a fast detector for packet motion. This single flight does not prove collision-free behavior of all2283 gather routes over complete periods.

A later all-checkpoints run selected the complete CUDA own-F for every full8192-site ring transition as well as GPU spatial/Flag backends. `stream28_dual_macrostep20_quiet_gpu_all_checkpoints_v1.json` **passed** in113.195 seconds with the same119-word decoded SHA and77 changes. The GPU spatial paths still independently cross-checked the CPU replay. This confirms that the whole-ring boundary results did not depend on the CPU native F backend.

`stream28_dual_macrostep20_quiet_gpu_primary_v1.json` **passed** in73.931 seconds, peak CPU RSS869436 KiB. It used CUDA complete F for all whole-ring checkpoints, CUDA spatial transitions for both complete65536-tick evaluator periods, and CUDA Flag recurrence for393216 suffix ticks. The GPU evaluator supplied all238 physical output event values to the Holder event checks; no CPU evaluator replay was called in this mode. At U−1, all119 decoded upper fields matched the intended upper local F,77 fields changed, and the SHA-256 was `4a1060b7f9ba6889afa0622ccd9aa6289ad58e0f2f5dfb1d2c79c19e9240cdc9`. Each GPU evaluator period took about3 seconds including encoding/readback, used19.33 MB on device and produced119 output events,26101 deliveries,14851 gates plus63 next-wrap gates. The earlier parity run independently established equality of its full physical evaluator states and events with CPU replay. One failed primary attempt exposed NumPy integer output-site indices at the Python typed Holder constructor; conversion to ordinary `int` and a regression test fixed that boundary without altering CUDA dynamics.

The result is a complete **event-composed clean-domain local upper work cycle with GPU physical computation**, not a continuous all-fields GPU U-step. CPU code still executes 34245 gather launches/receives, ten Holder SEND endpoint paths, and protected Holder commits; it skips packet flights using checked phase/distance contracts and reconstructs Holder state at selected boundaries. A fully GPU-resident sparse Holder/gather executor with on-device guards is the next engineering step. It must preserve all fivefold copies and mail/head/controller registers, execute or soundly jump each physical transition, and compare decoded successive upper macrosteps. Repair, damaged ROM behavior, finite-depth termination and noise amplification remain unproved.

A second GPU-primary run, `stream28_dual_macrostep20_age0_gpu_primary_v1.json`, used upper Age0, seed2026092928 and active Signal/Wf geometry. It **passed** in74.709 seconds, CPU peak854068 KiB. This is a distinct branch from the zero-Flag run, not a repetition of its state.

The third GPU-primary run, `stream28_dual_macrostep20_agewrap_gpu_primary_v1.json`, started with upper Age U−1 and the same seed2026092928. It **passed** in73.797 seconds; the simulated upper controller Age wrapped to0, all119 decoded fields matched the intended F,87 changed, and digest `f20252bdb4d1482d4df97af7a3b83e40eeeb280d99a0b98884175717964762de`. That digest exactly matches the earlier CPU event-composed Age-wrap fixture. This is still one macrostep for one local upper neighborhood, not two successive macrosteps on a closed upper ring.

The gather event engine now checks an additional physical flight invariant for every route: the exact signed path crosses the same number of colony boundaries as the packet's remaining counter. All34245 routes passed on the15-colony fixture (`stream28_dual_gather20_events_15_crossings_v2.json`,13.489 seconds). Previously the modulo-ring endpoint check could not distinguish a direct path from one with an extra15Q lap; a negative test injects precisely that false lap. Same-direction packet phase uniqueness, separate left/right tracks, literal source and receive steps, and unique target history words remain the other clean-domain premises. The check does not replace continuous simulation of packet interactions with heads, faults or arbitrary incoherent states.

Performance is meaningful only for this **one local upper neighborhood**. It uses15 lower colonies and takes about74 seconds wall time even with GPU physical computation because CPU endpoint/Holder checks dominate. Naively doing that separately for all8192 upper addresses would be impractical and would duplicate most lower cells. A closed two-level Q² ring contains67,108,864 physical cells. The present complete-F CUDA kernel stores421 64-bit words per cell:210.5 GiB per state buffer, or421 GiB double-buffered. A *new*, tightly bit-packed representation of its raw6465-bit state would require50.51 GiB per buffer, or101.02 GiB double-buffered, still beyond the80 GiB A100. The exact3063-bit projected evolving state would require23.93 GiB per buffer,47.86 GiB double-buffered; one healthy shared Address-static table adds only about3.32 MiB. This compression is a backend representation choice, not a physical alphabet change, and would need extra storage for damaged static-ROM sites. If one nevertheless extrapolates the measured0.847 seconds per tick for15 colonies linearly to Q² sites, a dense full-F tick would take about463 seconds and one U-period about15.4 years; two periods about30.8 years. Those are conditional estimates for the current full-F kernel, not measurements or projections for a redesigned packed kernel. A practical two-level GPU experiment therefore needs one shared packed ring, parallel sparse Holder/gather events, and on-device guards, rather than 8192 independent local audits.
