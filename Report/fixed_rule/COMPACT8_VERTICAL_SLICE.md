# Fixed 8Q compact evaluator: own-F circuit and continuous physical replay

2026-09-28. This follows [the full-state description and packing audit](OWN_RULE_DESCRIPTION_CAPACITY.md). It is a substantial one-level evaluator slice, **not yet a fixed-point hierarchical self-simulator**. Gray pp. 31–32 requires the projected hard-wired ProgramBit/static ROM to be a function of Address; Gács §9.2 allows a modified self-correcting rule. Here, the upper static words are still supplied during initialization, so those source requirements are not yet fulfilled.

## Why 8Q was selected as the fixed candidate window

The 4Q spatial rule and three-history compact vote have a 14,058-operation own-F description. An explicit-copy optimistic path reached Hold at tick 43,995, and an event schedule missed 4Q while completing its rightward operand network by tick 40,653. The failed 4Q receipt is `figs/fixed_rule/stream28_compact_operands_4q_fail_v1.json`; the successful but physically hypothetical 8Q operand schedule is `stream28_compact_operands_8q_v1.json`. That was a reason to *change the fixed rule*, not a reason to dispatch on hierarchy depth.

`spatial_epoch8.py` is one fixed radius-one, 8Q=65,536 local rule with the same three static gate slots, one dynamic operand pair/result, 38 route slots and one bidirectional packet register. It widens Age, two switch ages and 38 route launches by one bit: **2,375 bits/cell**. A marked output gate already stores its result in `source_value`; the changed rule lets an encoded leftward output route read that latch after later gate-slot reuse. No additional dynamic result register was added. The combined `stream28_compact_vote8.py` rule is fixed radius seven and **6,465 bits/cell**, including the existing holder maintenance and three-history in-place voter. Its stage ages are constants independent of represented hierarchy depth. The projected evolving state is **119 words/3,063 bits** (`stream28_compact_projected8.py`), with all holder controller copies and spatial Age, operands, result, output latch and mail retained. A static vote-marker mutation changes the projected local result; the two static ROM rows must be provided explicitly to the diagnostic lift.

The spatial component's complete 267-output WordCode description has **4,162** operations and matched 406 literal local states, including both mail directions, late latch, switches, wrap and collisions (`spatial8_description_full_v1.json`). The combined in-place-vote rule's 421-output/6,315-input full description has **22,486** operations. Existing typed identities and AND fusion reduce it to **14,761**, digest `619205eb513c1cafeada81d2e0770e0b695b22b09687cd4638ff9433f1ba210d`. Both descriptions matched 96 literal combined local states, including fivefold voting with one damaged replica per input and a late output route (`stream28_compact_vote8_local_v1.json`). These are explicit-input descriptions of the changed physical rule, including the evaluator's own transition; they are not an address-hard-wired closed ROM.

## Capacity, packet schedule and physical dataflow

The changed DAG uses 761 evolving input words and 390 address-indexed static inputs from the upper 15-cell neighborhood. Three history/vote sites per evolving word, 119 Info/Hold pairs, eight reserved sites and 298 scratch sites use **2,827** cells; reserving 390 static-word sources gives a gate area starting at site 3,217. With 4,970 available gate sites, the fixed three-slot alphabet offers 14,910 slots. The compiler placed **14,780 fanout copies plus two identity-buffer gates** for raw sources with 41 and 40 consumers, leaving 128 vacant slots but **no vacant gate-capable site**. Every site obeys the 38-route limit. Capacity receipt: `stream28_compact_vote8_capacity_v1.json`; static placement: `stream28_compact8_gate_packing_v1.json`. The 390 words are externally supplied values at this stage; the site reservation is not a solution to generating them from the evaluator's own address-indexed ROM.

The dependency-ordered placement gives an optimistic latest output of tick 35,570. A stricter event scheduler assigns the actual source copy to each use, enforces one active gate slot/site, waits for local switches, reserves rightward packet phases and allows target-slot pass-through laps. Its **25,862** operand packets and **14,782** gates finish at tick **34,225**, including 9,812 site switches, 1,767 packet laps and 843,935 one-tick phase waits. The 4Q rule's earlier schedule is not reused. With all rightward mail cleared, 119 distinct source sites launch leftward output packets at tick **34,226**. They occupy distinct phases and arrive at all 119 Hold sites by tick **39,804**, leaving **25,732 ticks** before the 8Q reset. Two output sources had switched to a later gate, which is why the changed latch-route semantics are necessary. Receipts: `stream28_compact8_operands_8q_v1.json` and `stream28_compact8_output_phase_8q_v1.json`.

`build_compact8_circuit.py` materializes one 8,192-cell physical initial state from a complete typed upper input neighborhood: 4,970 GATE cells, 1,144 used SOURCE cells, 119 OUTPUT/Hold cells, and 1,959 inert cells. Gate opcodes, literal/preloaded operands, switch ages, route targets, source slots and launch ages are in the encoded cells. `audit_compact8_output_endpoints.py` checked all 119 late source emissions, all 119 output receiver local steps, and all **595** fivefold holder Hold updates against the optimized own-F oracle. Receipt: `stream28_compact8_output_endpoints_v1.json`. The three-history gather layout has 2,283 analytical routes and all launch/accept endpoints checked, including 24 complete combined-rule endpoint steps (`stream28_compact_gather_v2.json`).

`replay_compact8_numpy.py` advances the encoded spatial dynamic state **at every tick**, reading only each cell's static gate/route data and evolving registers in its transition loop. It does not consult the DAG or schedule to produce transitions. The independent WordCode oracle and sampled literal local rule are diagnostics. A source-hashed two-period run evolved **131,072 consecutive ticks = 1,073,741,824 physical site-ticks**, with 25,981 packet emissions/deliveries and 14,782 gate completions **per period**, all 119 output words in each period, 106,496 literal local site-step comparisons at 13 full-ring times, and identical dynamic states at successive wraps. The run took about 48.5 seconds at peak 431,192 KiB RSS. Receipt: `figs/fixed_rule/stream28_compact8_continuous_2period_v2.json`. The first attempt's only failure was accounting for 86 gates that compute on the reset tick as belonging to the next period; that counter was corrected before the passing replay. The output values were tested from a randomly generated typed input neighborhood, but the *same* inputs were retained for both periods.

Focused current-source regressions include the 8Q spatial local tests, 8Q projected-state relation, both complete WordCode descriptions, all late output endpoints and a continuous one-period replay. The compact predecessor's 4Q/8Q distinguishing tests also remain green. This work used CPU and under 0.5 GiB RSS; no main-agent GPU job, shared CUDA artifact, historical data or shared report was touched.

## Remaining construction gap

The initial circuit still gets **390 upper static words from the host**. `stream28_compact_projected8.local_step` likewise receives static holder and spatial rows as diagnostic arguments. To obtain Gray's hard-wired self-simulation, the fixed physical rule must derive these words from its own address-indexed ROM, prove the ROM it queries is the same ROM generated from the resulting changed rule, and retain local correction of that ROM. A test ROM, an arbitrary input fixture or this executable circuit is not a fixed point. Adding a static lookup protocol changes the local rule and its description again; only 128 gate slots remain under the present site reservation, so capacity and timing must be remeasured after that change.

The three-history gather paths are locally checked, but **three complete gather stages, the stage-three Flag/Signal path, Info/History maintenance, and U=2^28 holder work period were not continuously evolved together with the 8Q circuit**. Two repeated isolated evaluator periods are not two decoded upper macrosteps. The active integrated clock is still U=2^28, not Gray's U≈2^20. Finite-depth termination, higher levels, damaged-colony repair and measured noise amplification remain unproved. The Flag2 persistence counterexample and computed-SimBit timing ambiguity from the baseline audit remain source-fidelity issues.

## Address projection of the spatial ROM

After the initial two-period replay, `compact8_address_rom.py` derived the **341 used spatial static input words** from the immutable circuit template at each canonical upper address. Its template comes from the same encoded 8,192-cell physical circuit used in the replay; no second spatial program is supplied. The projection preserves all evolving inputs and the **49 holder static inputs**. At seven representative center addresses, tests checked every spatial static wire against the corresponding physical ROM row, checked the encoded SOURCE values, and checked that the combined local transition reloads one address-derived value from fivefold holder Data at the actual stage-five capture age. This is an initial-data projection and one local capture test, not a whole holder work period or a fault repair proof.

The stronger continuous receipt `figs/fixed_rule/stream28_compact8_spatial_rom_continuous_2period_v1.json` passed two consecutive 8Q evaluator periods with the 341 spatial values address-derived at upper center address 3,217: **131,072 local ticks, 1,073,741,824 site-ticks, 238 correct Hold words**, 25,981 delivered packets and 14,782 completed gates per period. The physical rule SHA-256 and optimized description digest are unchanged. The 49 holder static words remain random external typed inputs in this experiment, and the host initialized SOURCE values directly; a whole-period holder Data reload was not run. The table projection does not establish a fixed-point self-ROM or successive upper macrosteps.

The immediate construction task is a compatible holder ROM for the compact three-history layout. The earlier holder ROM has 3,455 memory sites and 4,061 packed instruction rows; its stage-three path takes about **10,651,589 ticks** under its old layout. The new compact memory occupies 2,529 sites before scratch and static-source reservations. Simply grafting the old instruction rows onto the new memory would use stale operand addresses. The holder stage-three Flag/Signal procedure and its operand map must be rebuilt against the compact layout, then the 49 address-indexed holder static inputs can be tied to that resulting same ROM. This and the stage timing are the main blockers to the requested U≈2^20 and full hierarchical closure.

An exact backward slice of the **changed own-F** gives a more promising stage-three direction. `measure_compact8_flag_slice.py` pruned its 14,761-operation description to **450 operations** producing Flag1 and Flag2. It reads **56 evolving holder words, zero spatial words and zero static ROM words**. Thirty-two arbitrary typed neighborhoods matched the full rule; clean coherent geometry gave `(0,0)`, three right Flag1 cells gave `(1,0)`, and four left Flag2 cells gave `(0,1)`. Receipt: `figs/fixed_rule/compact8_flag_slice_v2.json`; two focused tests passed. This shows that the early flags can in principle be evaluated without rebuilding the 49-word holder ROM lookup first. The existing full encoded 8Q evaluator already calculates both: its scheduled output sources complete at ticks 24,111 and 25,251, and its Hold deliveries arrive by ticks 38,035 and 38,514. A candidate could run the **same encoded evaluator** once after the first vote, commit only those two outputs, then reset and run it again in stage five. That would reuse gate descriptions rather than consume a second set of slots. It remains a timing hypothesis: the current combined local rule invokes the spatial evaluator only in stage five, lacks the early capture/commit and flag-send controller, and has not been re-described or physically replayed with two invocations. The 450-operation slice is an analysis oracle, not a second transition kernel.

The old stage-three symbolic schedule spends **10,497,489 ticks** reaching its branch after the Flag1/Flag2 prefix, then **154,100 ticks** on ten SEND instructions and HALT under the old 7,517-site holder controller cycle. This suggests a concrete U≈2^20 route: three 8Q gather windows (196,608 ticks), one 8Q early pass (65,536), that old-layout SEND-tail allowance (154,100), a conservative 5Q packet flight (40,960), and one 8Q final pass (65,536) total **522,740 ticks** before other stage overhead. The sum is a feasibility budget, *not* a schedule: the gathers currently use 16Q frames, the old SEND operand addresses refer to the wrong compact memory map, and no dual-pass physical local rule exists. Each of those must be implemented and remeasured before reducing U.
