# Next construction: protect procedures without losing closure

This is an implementation design and set of obligations, **not verified behavior**.
It follows the single-Info-bit counterexample and the serial-vote locality result.
Neither the candidate-B nor serial-vote rule currently has this protection.

## Proposed state and locality

Gray pp.33–34 require five copies of every simulation bit, moving mail and
procedures, while retaining the raw local-structure rules. The next candidate
should keep one physical Address/Age/Flag1/Flag2 record and hold five overlapping
copies of Data, head, controller and mail words. Holder x's offset d record
represents logical site x+d, for d=-2..2. The pre-update majority for a logical
operand reads the five actual holders. A procedure whose logical operands are at
offsets -1,0,+1 then reads at most radius five. The serial-vote revision has removed
the current radius-two temporal-memory operation that violated this bound.

Do not apply this prescription blindly to the full radius-five rule: raw
maintenance remains its own component. Wf, Signal and maintenance gating need an
explicit derivation. In particular, reconstructing a neighbor's redundant Wf at
physical distance five could require radius seven. Likewise, computing the
maintenance result at x+d separately for each copy would extend the neighborhood.
The source's physical-holder clearing priorities must be respected.

A tentative scheme uses raw primary Wf in maintenance, and computes Wf from the
already redundant Signal protocol as currently done. Whether its backup semantics
and containment match Gray remains an **open choice requiring a distinguishing
fault test**. Omitting Wf from fivefold storage is not silently justified merely
because it is recomputed; old Wf participates in the next maintenance step.

## Avoid correlated geometry faults

Do not read one potentially damaged logical primary Address/Age and broadcast
that bad selector into all five redundant procedures. That could make every copy
wrong from one physical fault. A holder should derive virtual procedure addresses
from its own local geometry and execute each copy separately. If two physical
holders have bad geometry, their bad procedure copies can then be outvoted by
three good holders. This is only a proposed proof mechanism; damaged geometry,
clock resets and crossing colony boundaries all require tests.

For the healthy radius-one controller, holder x with copy offset d needs program
metadata at relative addresses d-1,d,d+1, hence offsets -3..3. One concrete
unprojected description can include seven static instruction records. The
projected hard-wiring derives all seven from the same physical Address, shifted
modulo the fixed Q. The simulated versions of **all seven** records must be
regenerated by physical META procedures using the computed simulated Address.
Keeping only the old single static record would leave a self-description gap.

The provisional projected width, if Data/head/control/mail (528 bits) are copied
fivefold and the existing seven other dynamic words remain, is 2,706 bits /
97 words. Seven static records add 1,386 bits / 49 words, giving a provisional
unprojected 4,092 bits / 146 words. These counts are **not final**: the Wf choice,
metadata selectors and any new fields must be included before freezing an
alphabet. They illustrate why the old Q/U budget cannot be reused without work.

## Required closure and fault gates

1. Define a total scalar local transition on every raw state, preserving radius
   five or explicitly documenting and fixing another radius once. Specify raw
   maintenance, all procedure copies, reset/commit, mail erasure, Address-change
   erasure, Signal and Wf priority on malformed as well as healthy states.
2. Generate a complete word description of that transition, including the
   expanded evaluator and hard-wiring machinery. Recompile the colony program
   to process every raw input/output word and regenerate every static record.
   A wrapper around the old ROM would still describe the wrong rule.
3. Measure description length, program/core size, each gather, six-NAND temporal
   votes, both complete evaluations and computed-flag deliveries. Select one Q/U
   only after these fit. Check index/address widths and tail-mail addressing;
   current packet targets and static indices are 32 bits.
4. Prove exact noiseless copy coherence on valid geometry, compare complete raw
   scalar/description/native outputs, and execute successive physical work
   periods. The raw encoding must include all copies, even inconsistent ones.
5. Test arbitrary one/two physical-holder faults in Data, live head/control, mail,
   Signal, Wf, Address and Age, separately and in combinations. Include faults at
   reset, final operand reads, WRITE, capture and commit. Require the expected
   clean decoded evolution outside the stated damage cone, not merely zero flags.
   Preserve counterexamples when a claimed recovery bound fails.
6. Keep initialization and diagnostic decoding separate from physical evolution.
   Depth 2/3 must use the same description and workspace, with actual controller
   state encoded in the same raw data relation. No depth-specific interpreter or
   host substitution of simulated transitions is introduced by this plan.

The ordinary cap proofs supply consistent terminal data for the current two
revisions. A revised redundant rule needs its own cap proof. No claim of measured
noise robustness or the Gács amplification hypotheses follows from local
one/two-fault tests alone.
